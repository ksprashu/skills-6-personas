By transitioning from **"Black Box Automation"** to **"Glass Box Orchestration"**, this skill gives you complete visibility, control, and learning opportunities during complex coding sessions. Mandatory Grounding

The Scout factual-grounder

The Scout establishes a verified knowledge baseline. Before drafting plans or proposing code structure, the Scout must inspect the repository's starting state and documentation.

  • Checks local files and configuration rules (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`).
  • Executes web search or MCP lookups if 3rd-party dependencies are involved.
  • Rejects all ungrounded assertions immediately.

Interactive Grilling

The Analyst idea-refiner

The Analyst challenges confirmation bias, pinpoints high-risk dependencies, and conducts an interactive dialogue (grilling session) to sharpen requirements before code is written.

  • Triggers interactive Socratic questionnaires for vague ideas.
  • Asks questions **one at a time** to prevent cognitive overload.
  • Uses the `/grill-me`, `grill-with-docs`, and `interview-me` skills implicitly.

Interactive Simulator

[Analyst]: I see we want to add an OAuth login flow. Before I structure the plan, let's refine this: Are we storing the tokens in-memory, or do we require secure local cookie storage? (Question 1/3)
Symmetrical Deconstruction

The Architect planner

The Architect maps out the structural, interface, and test roadmap. This splits design thinking from code implementation.

  • Drafts a structured `PLAN.md` with explicit milestones.
  • Clusters parallelizable independent tasks into execution batches.
  • Enforces the **Breakpoint Protocol**, prompting you before commencing execution.

Breakpoint Prompt Pattern

# 📐 Strategy Phase Approved
The tactical roadmap has been generated in `.gemini/PLAN.md`.

*Question:* Should we execute the full plan end-to-end, 
or would you prefer breakpoints at each transition?
Critique Loop + Sandboxing

The Builder sandbox-builder

The Builder runs the actual implementation swarms. To ensure state integrity, all operations are isolated in sandboxed directories and validated through rigorous unit-testing loops.

  • Isolates tasks in `.gemini/tasks/task-ID/` paths to avoid file conflicts.
  • Uses an autonomous `Implement -> Test -> Critique` verification cycle.
  • Stops immediately if it hits the **Circuit Breaker (`MAX_ITERATIONS=3`)** retry limit.

Evidence & Citation

The Sentry critic

The Sentry acts as a skeptical verifier, reviewing code and ensuring every decision is properly justified and mapped to verified logs.

  • Conducts multi-axis code reviews (security, performance, architectural fit).
  • Records and links outcomes to the **Evidence Ledger** (`EVIDENCE.md`).
  • Ensures strict citation hygiene: everything must reference `[E-XYZ]`.

Mentorship & Pedagogy

The Mentor educator

The Mentor translates completed code changes into accessible knowledge, mapping abstractions, explaining trade-offs, and ensuring you learn from every modification.

  • Builds conceptual mental models with Mermaid.js architecture diagrams.
  • Annotates critical code sections line-by-line.
  • Provides mini Socratic exercises to help you practice and verify understanding.
